# DUET CORE frontend

- Preserve FastAPI endpoints, payloads, RBAC and operational semantics. Backend changes require a documented, minimal, backward-compatible justification.
- The product is self-hosted. Do not add mandatory cloud services, analytics, CDNs or multitenancy assumptions.
- Keep UI copy in Brazilian Portuguese and preserve business terms. Never infer a final RPA state from request acceptance alone.
- Reuse semantic tokens from `frontend/src/styles/tokens.css`; support light, dark and system themes, keyboard focus, reduced motion and 320 px reflow.
- Keep server state inside domain hooks/services and interface state inside components. Render API/log content as untrusted text.
- Run `npm run lint`, `npm run build` and, with Vite running locally, `npm run test:visual` for shared-shell or responsive changes.
- Use `Button`/`IconButton`, `TextField`, `PremiumSelect`, semantic tokens and `useDialogFocus` for new or migrated interactive UI. Domain-specific controls may compose these primitives; do not create parallel generic button, field, select or modal behavior.
- Use `useInteraction` for confirmations and transient notifications. Do not introduce `window.alert`, `window.confirm` or `window.prompt`; destructive actions must explain impact and use typed confirmation when recovery is not available.
- Use the shared `services/api` client and `config/runtime` for HTTP and WebSocket endpoints. Keep environment-specific hosts out of components and hooks.
- Use `usePollingTask` for recurring server reads: do not overlap requests, keep useful stale data visible during refresh failures, and expose an explicit retry action.
- Keep `/component-lab` development-only and free of operational data/actions. Run `npm run test:components` after changing shared controls, focus, themes or motion.
- Track route coverage, evidence and remaining validation in `docs/frontend-reconstruction.md`. A successful build is not proof of full product reconstruction or backend integration.
- Keep `.github/workflows/quality.yml` aligned with local verification. New shared UI must pass lint, TypeScript/build, component audit and the responsive visual matrix before merge.
- Treat Alembic revisions as the schema source of truth. Never restore `create_all` as an upgrade mechanism; review autogenerated revisions and verify upgrade, downgrade and `alembic check` on disposable PostgreSQL.
- Preserve `X-Client-Request-ID`/`X-Request-ID` correlation and the `/health/live` versus `/health/ready` distinction. Health responses must not expose credentials, paths or operational payloads.
- Define explicit Pydantic response models when changing JSON APIs. Keep success/error states discriminated, validate external telemetry before serialization, and add a contract test so frontend fields cannot silently diverge from backend payloads.
- Never return raw exceptions, tracebacks or upstream response bodies to clients. Log controlled technical context with the request correlation ID and keep `tests/test_api_error_safety.py` passing.
- Use `core.timezone.local_now_naive` for Scheduler wall-clock decisions and expose `DUET_TIMEZONE` in schedule UX. Do not reintroduce host-local `datetime.now()` into scheduling flows or silently reinterpret persisted schedules.
- Preserve the schedule misfire contract: `run_once` recovers at most one delayed occurrence; `skip` records and advances it only after the configured grace window. Never replay an unbounded backlog or discard an occurrence without an explicit persisted policy.
- Preserve the execution queue contract: priority is `urgent > high > normal > low`, FIFO and execution ID break ties, and priority may change only through an atomic update while status is still `queued`. Keep `queued_at` as operational evidence and never reset it during dispatch retries.
- Treat Device connectivity, soft deletion and operational availability as separate states. Maintenance must require a visible reason, use the same per-Device advisory lock as reservations, preserve running/queued work and prevent new dispatch until an operator explicitly releases the Device.
- Derive Device health from the shared heartbeat policy, not browser time or ad hoc status checks. Keep `DUET_AGENT_HEARTBEAT_TIMEOUT_SECONDS`, the offline monitor and public health fields aligned; background refresh must preserve the last valid catalog on transient failure.
- Treat `RobotVersion` as an immutable release. Version catalogs may expose provenance and checksums, never server storage paths; historical downloads must resolve the exact version and validate its SHA-256 before sending bytes.
- A modal must make adjacent page content non-interactive in addition to trapping focus. Keep `useDialogFocus` responsible for scroll lock, Escape policy, temporary `inert`/`aria-hidden`, cleanup and focus restoration.
- Every modal and alert dialog must render through a portal in `document.body` and compose `ui-modal-backdrop` plus `ui-modal-surface`. Reuse the modal backdrop/surface tokens; domain CSS may change dimensions and layout, not overlay darkness, blur, border, radius or elevation.
- Scope Vault automation-credential reads by `folder_id`; never fetch the entire vault for a client-side folder filter. Search and clipboard actions must exclude secret fields, and refresh failures may preserve data only when it belongs to the same selected folder.
- Derive mutation affordances from the backend's exact RBAC permissions. Read-only users must keep useful access to permitted data without seeing controls they cannot execute; the server remains the final authorization authority.
- Keep Device catalog refresh errors separate from mutation errors. A successful heartbeat/catalog poll must never dismiss a failed create, edit, maintenance or bootstrap action; mutation feedback remains until explicit dismissal or retry.
- Keep the Automations information architecture split into `/automations/overview`, `/automations/build`, `/automations/catalog/robots` and `/automations/catalog/libraries`. Load only the active domain, preserve Development projects and immutable Robot releases as separate contracts, keep `/development` and `/robots` as compatible entry points, and preserve the Studio route until its backend/WebSocket contract is migrated deliberately.
- Include Agent token protection in readiness without returning secret material. A Control Room that cannot validate `DUET_AGENT_TOKEN_KEY` is alive but not operationally ready to create Devices.
- Build page identity with `PageHeader` and keep operational/live state in a separate status region; titles, descriptions and actions must retain the same hierarchy across routes.
- Build data-grid, list and operational-card identity with `PanelHeader`; preserve its 16 px heading scale, optional domain icon and dedicated action/status slot instead of restyling local `h2` elements.
- Build every catalog or table search with `SearchField`. Do not add local `input[type="search"]` wrappers, spacing or icons that diverge from the shared contract.
- Use `EmptyState fill` for selection-required or otherwise contextual states inside tall detail panels. The panel must expose a flex-column content area so icon, title, description and action remain centered together; keep ordinary table/list empty states content-sized.
- A visual hover, border or selected background must not promise a larger action than the native control provides. In composite rows, let the primary button fill every area not reserved for explicit expand/menu controls, expose the selection state accessibly, and verify both blank-area clicks and keyboard activation.
- Treat `ProjectStageHistory` as the authoritative Kanban movement audit trail and compose it into the project activity feed. Comment image attachments must remain authenticated, project-scoped, type/size validated and inaccessible by raw storage path.
- Keep hierarchical catalogs navigable as trees: sort siblings predictably, expose expansion and selection semantics, preserve the selected path when collapsing, show a searchable ancestor context, and let creation choose an explicit parent while previewing the destination path. Treat a JSON `status: error` as failure even when a legacy endpoint responds with HTTP 200.
